## Run locally

Use the repository's Node version in [frontend/.node-version](../../frontend/.node-version). The app
has an independent npm lockfile. From the repository root:

```sh
cd apps/mobile
npm ci
npm start
```

Open the project in an SDK 58-compatible Expo Go or a locally built Expo app. In **More**, save the
HTTPS origin of your Spellbook instance and sign in. Guest Search also works after setting the
server URL.

To run against the repository's localhost stack, follow
[Development startup](../../docs/operations/deployment.md#stable-server-site-and-optional-development).
Use `http://10.0.2.2:3000` from the Android emulator, or `http://127.0.0.1:3000` from an iOS
simulator. Use the actual frontend port if you override it. An Android device connected over USB can
use `adb reverse tcp:3000 tcp:3000` and `http://127.0.0.1:3000`. When building the development app
locally with `expo run:android` or `expo run:ios`, set `SPELLBOOK_LOCAL_HTTP=1` to enable native
HTTP access for that build. Production JavaScript requires HTTPS. For QR approval on a second
device, use a server whose public approval URL is reachable from that device.

## Check a change

Run these commands from this directory. Regenerate and commit the generated file when its consumed
OpenAPI operations or referenced schemas change.

```sh
npm run generate:api -- --check
npm run typecheck
npm run export
```

The export produces Android and iOS bundles in `dist/`. It verifies Metro compilation. Install an
actual app build to check native permissions and the device flows against your server.

## Build with EAS

Run these from `apps/mobile` using an authenticated EAS CLI and the owning Expo account. Run
`eas init` to link the app to that account's project. Confirm the Android package and iOS bundle
identifier in `app.json` before registering store apps.

```sh
eas build --platform android --profile preview
eas build --platform all --profile production
```

The preview profile builds an installable Android APK. An iOS preview build uses internal
distribution and requires registered devices. Production builds an Android App Bundle and an App
Store-signed iOS archive. Upload the AAB to Play Console and use
`eas submit --platform ios --profile production` for TestFlight or App Store submission once Apple
signing and App Store Connect are configured.

## Dependencies and data

Expo Router provides native stacks and bottom tabs. The Expo SDK, React Native and their routing
peers supply the app runtime. Lucide supplies the navigation and quantity icons, and
`react-native-qrcode-svg` renders the public device approval URL. Image Picker opens the system
camera and photo library. Image Manipulator normalizes the selected image to JPEG, and File System
passes the temporary file to Expo's native fetch. Expo Crypto creates mutation request IDs and local
session cache IDs.

The API client uses types generated by `openapi-typescript` from
[`contracts/openapi.json`](../../contracts/openapi.json). TypeScript stays on 5.9 to match the
generator's supported compiler versions. FastAPI owns account authorization, Inventory mutations,
Deck availability and Scan results.

Secure Store holds the bearer token with its server origin and session metadata. AsyncStorage holds
appearance and server preferences plus up to 12 recent Inventory pages, virtual Box pages and
Physical Box lists per active session. Cached data appears when a request cannot reach the server.
Offline Inventory controls are read-only. Physical Box lists require a password session. Sign-out, a
fixed password expiry and HTTP 401 clear the session and its cache. At the last known expiry of a
linked-device session, the app hides private data until the server confirms the token.

Writes go directly to the API. If a write is interrupted, the app retains its request ID and input
in memory for an explicit retry during that app session. If the app has restarted since the
interruption, refresh Inventory and check the result before making the change again.

Scan uploads a photo on explicit request and displays the returned status and candidates. On Android
it can recover a pending picker result after the system recreates the activity. The current Scan
worker can report that recognition is unavailable.
