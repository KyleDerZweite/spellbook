## Shared Deck UI

The route loads library summaries and one selected composition, with contextual search and inspector ownership requests rather than full Inventory. Inspector ownership has explicit loading/error state and cancels replaced requests. Native metadata forms compare original field baselines. Enhanced network or unexpected action errors retain mounted editors, drafts and pending request IDs without applying the framework page update. The route shows an inline unconfirmed-save alert and releases busy controls. It removes a pending request ID only after a successful update or redirect; an unchanged lost-response retry keeps that ID. A stale Description keeps the draft open and offers an explicit rebase to the saved revision. Native metadata failures with HTTP 409 or 400 return submitted details and original field baselines in a labeled server-rendered recovery form. Rebase submits the shown latest Description revision through the normal backend check, so another intervening save can conflict again. Retained name/format baselines preserve disjoint patches. ## Profile saved-state consumer

The root layout owns one cookie EventSource through [workspaceSavedState](../../frontend/src/lib/saved-state/workspace.svelte.ts). Its [transport and lease implementation](../../frontend/src/lib/saved-state/workspace.ts) owns account activation, reset/recovery epochs, hidden/online resume, coalesced session probes and one bounded read pipeline per mounted resource. Live requires OPEN plus an authorized reset; read failures retain stale state without changing transport readiness. Terminal expiry clears protected state and suppresses private SSR content, including header and Search mutation controls. Initial/native SSR hydration remains available. The first layout activation preserves freshly hydrated subscribers mounted before that activation; account replacement, stop and terminal expiry still clear their protected state. Later mounted Inventory or Deck server-load completion requests a fresh leased read instead of replacing synchronized snapshots or deleted-target state. Native Inventory context transitions retain the requested offset through that bounded read. Direct Deck search captures the submitted query through body decode. Ordinary rerenders cannot restart an expired activation; a non-shallow navigation establishes a new activation only after a fresh no-store session response proves the same account. Failed, unauthenticated, superseded or late proof retains terminal clearing.

The [Profile adapter](../../frontend/src/lib/saved-state/profile.svelte.ts) retains the saved Profile/header interface and subscribes to Profile, Inventory and Deck changes. Dashboard reads server aggregates, Inventory refreshes its current window and active details, Deck refreshes library metadata plus the selected composition/availability and active contextual ownership, and Scan reads bounded recent sessions plus the selected result. Inactive routes register no readers. [The application contract](./application-contract.md#saved-state-synchronization) owns topic dependencies and transport authority.

Read leases check account, registration, recovery epoch, desired freshness and local writes before publishing and after decoding or awaited UI work. Writes acquire counted, idempotent handles before POST and release after acknowledgement or failure handling. Completion requests current saved state without changing original retry IDs or treating a lost response as confirmed. Ordinary Inventory invalidation drains active page work within its existing three permits, prunes queued plans and lazily restores the current logical anchor; true query or terminal changes retain their cancellation ownership.

Settings email, card fields/artwork, avatar selection, Inventory Notes/quantity, Deck Description/metadata/Inspector and Scan review choices remain separate from saved snapshots. Remote reads update clean fields only and preserve dirty fields with their original bases. Local Profile and Deck Inspector actions return compact confirmed field acknowledgements; only submitted fields advance their bases, preserving newer drafts. Deleted targets retain drafts with unavailable submission state. Scan candidate arrivals do not select or confirm a printing, and a changed photo requires explicit review. Native forms retain their normal server loads and do not require streaming. Source and automated integration evidence do not establish current-head rendered acceptance or deployed proxy behavior; those remain separately recorded with [slice 9](https://github.com/KyleDerZweite/spellbook/issues/182).

## Inventory bounded loading

## Runtime compatibility

The application targets Node 26 and pnpm 12, with the Node version in [`frontend/.node-version`](../../frontend/.node-version) and package-manager pin in [root package.json](../../package.json). Root pnpm workspace manifests and lockfile own installs across frontend, backend and contracts. Node 26 is a stable Current release on 2026-10-03, not yet LTS. The [Node schedule](https://github.com/nodejs/Release/blob/main/schedule.json) starts its LTS phase on 2026-10-28 and supports the release through 2029-04-30.

The implemented stack uses Svelte 5, SvelteKit 3, adapter-node 6, and Tailwind 4. The [Kit 3 migration](https://github.com/sveltejs/kit/blob/main/documentation/docs/60-appendix/35-migrating-to-sveltekit-3.md) moves configuration into the SvelteKit Vite plugin. Application imports use the `#lib/*` package mapping, and [`src/env.ts`](../../frontend/src/env.ts) declares environment variables exposed through the framework's environment modules.

Application type checking uses TypeScript 7 through the `typescript-native` alias. Kit 3 and svelte-check still require TypeScript 6's compiler API. Installing TypeScript 7 as that API dependency fails because it does not provide the expected `ts.sys.readFile` interface. The compatibility dependency supports those tools; it does not replace the project's TypeScript 7 check. The [verification workflow](../operations/github-automation.md#local-checks) owns the commands.

[Root pnpm-workspace.yaml](../../pnpm-workspace.yaml) retains the patched esbuild dependency for Drizzle's legacy loader. Its scoped `runed` peer rule accepts Kit 3 because Bits UI uses the framework-independent entry point, not `runed/kit`. The [root lockfile](../../pnpm-lock.yaml) preserves these choices. Commands invoked from `frontend/` resolve the same root workspace; there is no separate frontend lockfile.

`APP_ORIGIN` configures `paths.origin` at build time in [`vite.config.ts`](../../frontend/vite.config.ts). Vite development instead uses `DEV_APP_ORIGIN`, defaulting to `http://localhost:5173`, from the single root `.env` or caller environment. The local launcher passes that origin to its children. Compose passes `APP_ORIGIN` to both frontend and migration builds. Adapter-node 6 no longer reads runtime `ORIGIN`; changing the public origin requires rebuilding the frontend. [Deployment](../operations/deployment.md) owns the operator procedure.

The application serves its machine-readable API contract at `/openapi.json`. It describes local authentication, account Profile/Dashboard/password/session operations and MTG API operations, including typed requests, responses, and cookie or bearer authentication. The route implementation remains the source of truth for error conditions and transaction behavior.
