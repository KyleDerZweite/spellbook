The SvelteKit application renders pages and owns HTTP adapters. Its named server composition privately consumes the shared database resource and exports backend Catalog, Auth, Profile, Dashboard, Inventory, Deck and SavedState use cases. The named database compatibility adapter injects database/build-analysis configuration and constructs the single backend resource, retaining raw handles for allowed legacy consumers. Other feature repositories remain enumerated compatibility code under the [application contract](./application-contract.md#implementation-status). Svelte components and Tailwind styles implement the interface; Bits UI supplies accessible interactive components. The [selected component guidance](../reference/ui-libraries.md) owns shadcn-svelte source adoption and its boundary with existing Bits UI controls. The shared stylesheet defines the neutral light and dark, icon-accented card workspace design described in [design direction](../product/ui-design-direction.md).

The root `/` always renders the shared [PublicLanding](../../frontend/src/lib/components/showcase/PublicLanding.svelte), including for signed-in users. Its native GET search form targets public `/mtg/search` with the query in `q`. With JavaScript, it opens the shared Search overlay above the mounted landing page. The private `/mtg/dashboard` is a separate account workspace. [The product specification](../product/specification.md#dashboard) owns its summaries and limits.

The public root uses Background with an interactive Commander deckbox and shared design tokens. The previous ownership example, isolated card-and-pack strip, oversized Spellbook headings, numbered comparison routes and `/fonts` page are removed. The `review=landing` composition override is also removed; local landing review uses `/`.

[LandingBackdrop](../../frontend/src/lib/components/showcase/LandingBackdrop.svelte) owns Background. Its right-aligned diagonal field has six columns and six rows of decorative tiles mixing Magic, Pokémon, Yu-Gi-Oh! and Digimon. Its 36 tiles contain 27 cards and nine packs. All four games have pack artwork. Tile widths scale with the viewport. Partial cards remain visible at softly faded edges. Desktop actions are vertically centered on the left, and the deckbox sits in the lower-right corner. Mobile places the right-aligned deckbox after the actions in the normal page flow.

[LandingCommander](../../frontend/src/lib/components/showcase/LandingCommander.svelte) owns the filled CSS 3D deckbox. Seven cards sit inside the open box; the Commander appears once in its front window. Selecting a seated card partially withdraws it without changing its orientation, scale or camera. Box walls cover the hidden portions and block pointer selection through them. Hover, focus or tap selects one of eight real deck cards directly. Arrow keys, Home and End move focus; separate previous and next controls provide 44-pixel targets. There is no automatic cycling. Reduced motion removes the transition while preserving selection. The Commander format label reuses the deck editor's `--color-role-commander` token. Deck name, format, 100-card count, color identity, creator and Archidekt source remain visible. This is a complete static public snapshot, with no account import, inventory comparison, internal public deck page or live synchronization. The [asset reference](../reference/website-icons.md#card-showcase-assets) owns provenance and refresh boundaries.

The root [Shell](../../frontend/src/lib/components/layout/Shell.svelte) renders the same [Nav](../../frontend/src/lib/components/layout/Nav.svelte), scrolling content and footer for every page, including login, registration, legal and error pages. There is no separate authentication header. The full-width header places the brand left, navigation in the center, and game, theme and account controls right. Shared `nav-link` styles cover navigation and the direct Sign in entry; the current entry uses the same underline state. Search, Inventory, Decks, Scan, Dashboard and Settings share `.workspace-container`, with width `min(calc(100% - 2rem), var(--layout-wide-width))`. The shared outer limit is `clamp(72rem, 84vw, 150rem)`. The landing uses this limit with responsive padding. Public home and hero use column flex layouts to fill the space remaining after the header and actual footer content. Short viewports scroll naturally. Background tiles and the deckbox scale within separate bounds, while action text stays at its normal size.

[AccountLayout](../../frontend/src/lib/components/auth/AccountLayout.svelte) owns the shared login and registration form frame, selected logo and functional heading. Its narrow content centers within the shell on desktop and starts beneath the header on mobile. [PasswordInput](../../frontend/src/lib/components/auth/PasswordInput.svelte) owns the native password input and its 44-pixel Show/Hide control. Visibility changes the type of the existing input without replacing it; callers retain labels, autocomplete, length constraints and error associations. The pages retain their form actions, pending state and login destination. Legal text and account forms keep readable content widths inside the common shell.

[The Settings layout](../../frontend/src/routes/settings/+layout.svelte) centers a bounded 1120-pixel composition inside the shared workspace. It supplies Profile, Profile Card and Password route links, with an underline for the current page. Below 1100 pixels the links wrap above the content. Profile owns optional contact email, the saved card and its Edit Card link. [AvatarEditor](../../frontend/src/lib/components/profile/AvatarEditor.svelte) opens a Bits Dialog around the shared sprite picker. It copies the saved avatar into a draft on open, discards cancelled selections, retains failed selections and closes after a successful save. The selected radio receives focus on open; the trigger receives it on close. Password uses the existing native PasswordInput with current, new and confirmation fields, independent submission state and no returned password values.

[ProfileCard](../../frontend/src/lib/components/profile/ProfileCard.svelte) renders the private MTG-style account card from a validated definition, username, avatar, artwork and account-scoped totals. It owns no queries or persistence. [ProfileFrameRegion](../../frontend/src/lib/components/profile/ProfileFrameRegion.svelte) displays cropped regions of the lossless CardCraft frame while keeping content in normal DOM flow. Header, type, rules and Power/Toughness regions can grow; crown, corner and footer slices retain their geometry. Artwork uses the common transparent source rectangle with `object-fit: contain`. The optional Power/Toughness capsule is a local crop of the corresponding Creature frame, not an upstream standalone layer. [Asset provenance](../reference/website-icons.md#profile-card-frames) owns source hashes and preparation. The shared [profile card contract](../../contracts/src/profile-card.ts) owns field limits, frame choices, mana grammar, KPI names, defaults and validation. The frontend [profile renderer helpers](../../frontend/src/lib/profile/card.ts) own current-metric resolution, text segments and KPI insertion. [ProfileCardEditor](../../frontend/src/lib/components/profile/ProfileCardEditor.svelte) owns editable card controls. Shared [ProfileTextField](../../frontend/src/lib/components/profile/ProfileTextField.svelte) and [KpiInsert](../../frontend/src/lib/components/profile/KpiInsert.svelte) insert placeholders using ActionMenu and restore field focus. The Profile Card route owns the reactive draft, saved/error status, authenticated card/artwork submission and height-aware sticky preview. It retains rejected inputs and focuses the first invalid field after controls are enabled. The shared [ArtworkPicker](../../frontend/src/lib/components/profile/ArtworkPicker.svelte) supplies native radios with complete 3:2 images in registration and the editor; [AvatarPicker](../../frontend/src/lib/components/profile/AvatarPicker.svelte) owns sprite choices. The backend Profile use case loads the stored definition independently of aggregate MTG totals so unavailable metrics do not block customization. Enhanced submissions send edited fields; native submissions include saved card/artwork baselines and derive the changed fields before calling the same Profile patch. Unchanged submissions authenticate without writing. The artwork registry owns allowed IDs and fallbacks; [authentication](./auth.md) owns independent account-scoped persistence. Generated artwork and choice images remain local WebP assets with provenance in [the asset manifest](../../frontend/brand/profile-artwork.json).

[SearchBar](../../frontend/src/lib/components/search/SearchBar.svelte) owns the shared labeled search input and clear action. Optional `name` and `submitLabel` props support the landing form. PublicLanding retains a native GET fallback and a SvelteKit snapshot that restores its input on browser Back. Empty submission opens the unfiltered catalog. The disabled App coming soon action appears in the signed-in account menu and mobile navigation, with no download destination or release-date promise.

[SearchOverlay](../../frontend/src/lib/components/search/SearchOverlay.svelte) owns navigation and the single Ctrl+K or Cmd+K listener. A normal primary Search navigation click opens its large desktop dialog or full-height mobile dialog, keeping the underlying page mounted. Modified clicks retain the real `/mtg/search` link. Query and the four filter categories serialize into the visible URL through SvelteKit shallow routing. Close, Escape and browser Back restore the background; Forward reopens Search. Full view replaces the overlay history entry with the real Search route. A direct URL or reload renders that route. The [root-layout Search session](../../frontend/src/lib/search/session.svelte.ts) is instance-scoped and retains query, filters, catalog cache and result position across those transitions. [SearchWorkspace](../../frontend/src/lib/components/search/SearchWorkspace.svelte) supplies the same controls and results to both hosts. Opening Search on the full route focuses its existing workspace. The deck editor retains its separate contextual search.

Shared application tokens use the selected Marcellus display face with a serif fallback and IBM Plex Mono interface face with monospace fallbacks. Marcellus remains provisional, but only an explicit user instruction may change the selected heading font; agents must not replace it autonomously. Font selectors, optional comparison font loading and the `font` and `uiFont` query overrides are removed. [Design direction](../product/ui-design-direction.md) owns the accepted content and visual requirements.

The synchronous `static/theme.js` bootstrap owns theme preference, local storage, system appearance changes, and browser theme color. It runs before page content to avoid a mismatched initial palette. The shared header's `ThemeToggle` controls that bootstrap through browser events on every page. Storage failure leaves the control functional for the current page.

The shared [ScrollArea](../../frontend/src/lib/components/ui/scroll-area/ScrollArea.svelte) owns the Bits viewport and themed scrollbar for Shell, Search panes, Inventory set choices and shared menus. Its positioned viewport contains absolutely positioned screen-reader helpers within the scroller, preventing those helpers from extending an outer scroll range. Callers bind the actual viewport for scroll measurement and restoration. Shell passes that viewport to Nav for scroll-based label collapse and captures its position through SvelteKit snapshots for browser Back and Forward. Navigation and restoration cancel pending wheel motion. A new pathname starts at the top; same-page query changes and form updates preserve the current position. [Selected UI components](../reference/ui-libraries.md) owns the scroll input contract.

The shell defines `--app-header-height` for desktop and mobile. `.app-main` contains the viewport with a reserved scrollbar gutter. The initial header clearance belongs to `.app-content`, so sticky descendants apply the header offset only once. The deck summary and catalog use that shared value. Navigation underlines remain visible when labels collapse to icons. Shared CSS retains themed native scrollbars for other scroll containers.

[Routing and games](../product/routing-and-games.md) owns the route list and legacy redirects. [The product specification](../product/specification.md) owns workflow behavior and acceptance criteria.

The shared [error page](../../frontend/src/routes/+error.svelte) uses the existing shell and control styles. Missing pages offer Search and Home links; server errors also offer a retry of the current page.

[CardInspector](../../frontend/src/lib/components/cards/CardInspector.svelte) owns shared printing selection and inspector content. Search renders it inline with Back to results inside its workspace. The Inventory route owns URL-backed query state, quantity/Notes drafts, stable inspector documents, pending entry IDs and logical focus. It renders bounded server results through InventoryWindow and VirtualInventoryList. Page eviction prunes row references and height measurements while retaining small focused, dialog and pending snapshots. GroupDirectory prunes its rendered references. Authorized location reads support entry anchors and surviving neighbors after removal. The list observes cache-version changes so arrived entries render even when visible indexes stay unchanged. [The state contract](./application-contract.md#frontend-state-and-shared-controls) owns guarded location/page/scroll restoration and bounded revision retries; local rendered arrival and anchor evidence is recorded with [slice 3](https://github.com/KyleDerZweite/spellbook/issues/176). The route retains Add cards/Search overlay, Add another printing selection, native form actions and group dialogs. Shared Button, WorkspaceHeader and QuantityControl supply Inventory control geometry; Deck adoption remains planned. [The application contract](./application-contract.md#frontend-state-and-shared-controls) owns cache and geometry limits, and [card grouping](../product/card-grouping.md) owns group semantics. The pure [inventory view helper](../../frontend/src/lib/mtg/inventory-view.ts) retains order transitions, set badge colors and New-badge presentation without owning full-data filtering. Server page metadata supplies complete set choices, progress, counts and an ISO timestamp; the route keeps legacy Date conversion local to native presentation.

Inventory enhanced forms retain unchanged unconfirmed intent IDs, drafts and their original Notes/quantity baselines. Network/error action results stay inline and do not enter the framework ErrorPage. Confirmed receipts clear their pending intent before bounded refetch; refresh failure cannot turn a confirmed write into a new addition. Web forms derive only changed fields, preserving concurrent disjoint quantity/Notes edits. Notes conflict exposes latest saved text and an explicit rebase control. Native row Details links open the authorized SSR `/mtg/inventory/[entryId]` page with Notes, Groups and reviewed Remove forms, preserving filters/offset. Expected native validation/conflict failures render the submitted Notes/base in the Inventory page without hydration. The native Groups directory supplies create/rename/delete forms; browser acceptance for these Slice 4 additions remains a separate current-head check.

[CardQuickAdd](../../frontend/src/lib/components/cards/CardQuickAdd.svelte) owns Search's enhanced inventory form, submission state and local result feedback. It reports pending state to its host through a callback. Additions stay disabled until the active printing supplies an available supported finish. Pending additions block printing changes and dismissal. The absolute `/mtg/search?/addToInventory` server action remains the authenticated mutation boundary even over another route. Confirmed additions refresh background page data with `refreshAll` while preserving shallow history state and form inputs. A refresh failure keeps the confirmed success and asks for a page refresh. Unconfirmed unchanged retries retain their request ID; a confirmed subsequent Add creates a new intent. The [product specification](../product/specification.md#catalog-and-printing-identity) owns the pending, input-retention and retry contract.

Deck server loads/actions now use the backend [Deck application](./application-contract.md#implemented-deck-application-boundary). The route loads library summaries and one selected composition, with contextual search and inspector ownership requests rather than full Inventory. Inspector ownership has explicit loading/error state and cancels replaced requests. Native metadata forms compare original field baselines. Enhanced network or unexpected action errors retain mounted editors, drafts and pending request IDs without applying the framework page update. The route shows an inline unconfirmed-save alert and releases busy controls. It removes a pending request ID only after a successful update or redirect; an unchanged lost-response retry keeps that ID. A stale Description keeps the draft open and offers an explicit rebase to the saved revision. Native metadata failures with HTTP 409 or 400 return submitted details and original field baselines in a labeled server-rendered recovery form. Rebase submits the shown latest Description revision through the normal backend check, so another intervening save can conflict again. Retained name/format baselines preserve disjoint patches. No-JavaScript browser recovery acceptance remains pending. These mechanisms preserve the existing Deck layout. Shared Deck UI consolidation remains slice 6; current-head browser acceptance remains separate.

Server loads and actions use the same Postgres repositories as `/api/mobile/v1/mtg/...`. Repositories scope mutations and reads to the authenticated account. The API keeps its existing MTG path segment for compatibility.

Public browser search, authenticated import resolution, and external API search use the same PostgreSQL [catalog](./catalog.md) through SvelteKit. Browser requests can carry the local session cookie, but public catalog reads do not require it. No catalog key or separate search origin is required.

Search starts without selected filters. [CatalogWindow](../../frontend/src/lib/search/catalogWindow.ts) owns addressable result pages, request cancellation, bounded caches and generation coherence. [VirtualCardGrid](../../frontend/src/lib/components/cards/VirtualCardGrid.svelte) owns layout and visible absolute indexes across the full result total. The [catalog document](./catalog.md#browser-result-window) owns page and cache limits. Full Search fills the space remaining after the shared header and footer, with a minimum working height for short screens. Its results viewport owns grid scrolling so virtual ranges follow the visible rows. Search captures its scroll position before navigation and ignores teardown scroll events, preserving the position across Full view and browser history. Search prewarms up to 12 adjacent card image URLs after a 120-millisecond delay, skips Save-Data and 2G connections, and bounds its URL history. This client behavior does not change either search API contract.

[SearchWorkspace](../../frontend/src/lib/components/search/SearchWorkspace.svelte) reserves a 288-pixel desktop sidebar and uses shared ScrollArea viewports for the sidebar and results. VirtualCardGrid measures and restores the actual results viewport. [SearchFilters](../../frontend/src/lib/components/search/SearchFilters.svelte) reuses Bits UI Collapsible for each group and shows selections in the controls. ## Profile saved-state consumer

The root layout owns one cookie EventSource for the mounted authenticated account through [savedProfile](../../frontend/src/lib/saved-state/profile.svelte.ts). Profile reset/invalidation and resume/online fetch current saved Profile data, with one read and a coalesced follow-up. Account generation and abort checks reject late responses. Stream or read failure shows unavailable synchronization state on Profile pages. A successful Profile read restores live status only when EventSource is OPEN and backend reset has established healthy transport. Read failure preserves a genuine recovering state; a queued invalidation still starts its coalesced follow-up after a failed read. Auth expiry closes the stream, aborts reads, clears saved Profile/header state and unmounts protected route content. A new account starts with fresh state.

Settings email, card fields/artwork and an open avatar selection update only when clean against their last rendered saved baseline. Dirty fields retain their values and original baselines through remote refetch. Native card baseline inputs still derive field-specific patches. Successful local form reloads seed the saved Profile snapshot. Existing no-JavaScript forms, layout and preview/focus behavior remain. Standalone two-client browser checks cover Profile saved updates, dirty fields, unrelated-account isolation, reconnect, failed-read recovery and expiry cleanup. Inventory/Deck/Scan workspace consumers remain slice 9; deployment/proxy verification is separate. [The transport contract](./application-contract.md#saved-state-synchronization) owns connection/recovery mechanisms.

## Inventory bounded loading

Inventory now loads revisioned backend pages instead of a full read snapshot. Filtering, ordering, matching counts and group metadata cover the complete owned dataset. Native GET filters and one-based Previous/Next links provide bounded no-JavaScript navigation; enhanced rendering loads visible and adjacent ranges in the existing ScrollArea viewport. The [query contract](./application-contract.md#inventory-query-contract) owns ordering and consistency, and the [state contract](./application-contract.md#frontend-state-and-shared-controls) owns cache, drafts and focus. The declared local browser and representative-scale evidence is tied to the verified implementation in [slice 3](https://github.com/KyleDerZweite/spellbook/issues/176); performance on other hardware requires its own measurement. Compact Inventory mutation responses are implemented in slice 4; Inventory workspace synchronization remains planned for slice 9.

Form actions and Search background history follow the effective current URL rather than SvelteKit's older rendered URL. Successful enhanced Inventory and Group forms refresh the current bounded window without navigating to old filters. The [state contract](./application-contract.md#frontend-state-and-shared-controls) owns offset, anchor and submitted-draft guards; native forms and redirects retain their existing navigation.

## Runtime compatibility

The application targets Node 26 and pnpm 12, with the Node version in [`frontend/.node-version`](../../frontend/.node-version) and package-manager pin in [root package.json](../../package.json). Root pnpm workspace manifests and lockfile own installs across frontend, backend and contracts. Node 26 is a stable Current release on 2026-10-03, not yet LTS. The [Node schedule](https://github.com/nodejs/Release/blob/main/schedule.json) starts its LTS phase on 2026-10-28 and supports the release through 2029-04-30.

The implemented stack uses Svelte 5, SvelteKit 3, adapter-node 6, and Tailwind 4. The [Kit 3 migration](https://github.com/sveltejs/kit/blob/main/documentation/docs/60-appendix/35-migrating-to-sveltekit-3.md) moves configuration into the SvelteKit Vite plugin. Application imports use the `#lib/*` package mapping, and [`src/env.ts`](../../frontend/src/env.ts) declares environment variables exposed through the framework's environment modules.

Application type checking uses TypeScript 7 through the `typescript-native` alias. Kit 3 and svelte-check still require TypeScript 6's compiler API. Installing TypeScript 7 as that API dependency fails because it does not provide the expected `ts.sys.readFile` interface. The compatibility dependency supports those tools; it does not replace the project's TypeScript 7 check. The [verification workflow](../operations/github-automation.md#local-checks) owns the commands.

[Root pnpm-workspace.yaml](../../pnpm-workspace.yaml) retains the patched esbuild dependency for Drizzle's legacy loader. Its scoped `runed` peer rule accepts Kit 3 because Bits UI uses the framework-independent entry point, not `runed/kit`. The [root lockfile](../../pnpm-lock.yaml) preserves these choices. Commands invoked from `frontend/` resolve the same root workspace; there is no separate frontend lockfile.

`APP_ORIGIN` configures `paths.origin` at build time in [`vite.config.ts`](../../frontend/vite.config.ts). Compose passes it to both frontend and migration builds. Adapter-node 6 no longer reads runtime `ORIGIN`; changing the public origin requires rebuilding the frontend. [Deployment](../operations/deployment.md) owns the operator procedure.

The application serves its machine-readable API contract at `/openapi.json`. It describes local authentication, account Profile/Dashboard/password/session operations and MTG API operations, including typed requests, responses, and cookie or bearer authentication. The route implementation remains the source of truth for error conditions and transaction behavior.
