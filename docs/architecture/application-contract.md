## Module ownership

Keep SvelteKit and PostgreSQL in one deployment. Use root workspace packages `frontend/`, `backend/` and `contracts/` with existing dependencies. Preserve pinned runtimes, dependency patches, peer rules, migration history and lock/cache ownership. Frozen install, development, tests, production package resolution, containers, migrator, operator commands and CI must migrate together.

Contracts owns explicit JSON-safe requests, DTOs and discriminated errors. Timestamps are ISO strings and revisions are opaque decimal strings. Contracts imports neither implementation, database rows, platform APIs nor framework types. Backend owns trusted actor authentication, account authorization, validated use cases, persistence, transactions and artifact storage. Frontend owns presentation, navigation, HTTP parsing and origin policy, cookies and conversion into native forms or HTTP responses.

Use small application interfaces for Auth/Profile, Catalog, Inventory/Groups, Decks, Scan, Valuation/Costs/History and Categories. Backend maps DTOs at that interface so in-process web adapters and public HTTP adapters receive the same serialized semantics. The named frontend server composition adapter supplies feature configuration and constructs backend use cases without exposing raw database handles. Browser modules never import backend. Backend never imports frontend or SvelteKit helpers.

Check imports with the existing TypeScript compiler API, resolving aliases, type imports, dynamic imports and re-exports. Deliberately forbidden imports and built client output verify enforcement. During expand and contract, an enumerated server compatibility allowlist permits existing callers without allowing new frontend persistence or backend-to-frontend dependencies. Remove adapters only after all callers migrate. Independent deployments, a complete external HTTP adapter for every web call and the separate app remain later work.

## Adapter and mutation contracts

This section retains the accepted target across features. Implemented Inventory read/write participation, remaining legacy Inventory responses and implemented Deck contracts are distinguished below.

Web and public API adapters call the same authorized use cases for local authentication/session inspection, preferences, password rotation, Profile Card/artwork, Dashboard, Catalog enrichment, Inventory/Groups, Deck create/edit/import/export/role/printing/availability/search operations, and Scan upload/review/commit. Preserve public paths and map safe errors consistently. Server Dashboard summaries and selected-deck availability must avoid transferring full Inventory or account mutation-request history.

Q56 approved changing experimental v1 wire contracts in place. Bounded Inventory reads replace snapshots; mutation, import and Scan responses become compact; Notes/Description writes require their field revision. For each migrated operation, document old and new requests/responses in OpenAPI and migration notes. Existing consumers are not automatically compatible. No legacy route may bypass stale-text protection or remain an unbounded internal refresh path.

Backend authentication supplies the actor. Caller account IDs confer no authority. Quantity deltas carry a stable request ID. The account-scoped fingerprint binds the normalized payload and rejects changed-payload reuse. Persist the minimal original acknowledgement in the writing transaction, including request identity, affected stable entity identities, applied change, revision and removed identities. Replay returns this original acknowledgement after later edits or deletion/recreation. Clients fetch current state separately. Keep the documented legacy treatment of null fingerprints.

Patch only supplied fields. Avatar and selection fields use the last successful save. Disjoint patches preserve independent changes. Notes and Description use independent revisions that quantity and unrelated metadata do not advance. A stale save returns the latest saved field and revision; the frontend retains its draft and original base revision.

All Inventory writers lock the Inventory parent before entries before groups. Scan commit keeps Scan-session-before-Inventory order; Inventory and cost operations never acquire a Scan session afterward. Shared transaction helpers compose atomic bulk/import and Scan operations. Before bounded reads activate, every entry, group, membership, reorder, import and Scan writer must advance the monotonic Inventory revision in its writing transaction. Successful semantic changes advance it; retries and no-ops do not. This query revision is separate from field revisions.

Ordinary quantity changes and removal neither scan/rewrite unrelated positions nor return all entries. Explicit reorder keeps its separate behavior. Row decrement stops at one; confirmed Remove remains a separate action. Printing replacement is a semantic operation that preserves source identity/provenance, rather than remove/add copying.

## Implemented Inventory read boundary

The backend [Inventory reader](../../backend/src/inventory/read.ts) authenticates its actor and returns page, detail and location DTOs from [inventory.ts](../../contracts/src/inventory.ts). Reads use a repeatable-read, read-only transaction and never create an Inventory parent. The [query normalizer](../../backend/src/inventory/query.ts) is shared by HTTP and native GET adapters. Metadata retained outside the page cache contains no hidden entry or membership snapshot.

The [Inventory mutation use cases](../../backend/src/inventory/mutations.ts) authenticate a session-produced actor, lock the Profile/account row and revalidate the session before writes. Scan commits then lock the owned ScanSession; all writes lock the MTG Inventory parent, sorted existing entry IDs and sorted target Group IDs. Catalog resolution runs before parent locking. All operations in one bulk/import/Scan commit succeed atomically or roll back together. Notes changes advance only the independent Notes revision; omitted Notes preserve the current text. A stale Notes intent returns the latest owned text/revision and preserves the frontend draft for explicit rebase. Ordinary signed row deltas floor at one. Reviewed Remove binds the expected quantity under the lock; explicit absolute/bulk removals retain their earlier semantics. Ordinary writes preserve sparse positions and return compact receipts, with no account snapshot or unrelated position reflow.

The account/request journal atomically stores normalized fingerprints and the original acknowledgement. Authenticated replay precedes Catalog lookup, subject existence and current preconditions, surviving later edits, entry deletion/recreation and Group deletion. Changed normalized intent returns 409. Imports fingerprint normalized source text, defaults and source before resolution. Legacy null fingerprints retain no-repeat behavior; missing historical receipts return an explicit empty `legacy: true` acknowledgement, never reconstructed current state. Older non-null fingerprints remain strict and may reject clients migrated to the new normalized shape; callers must not replace an uncertain old request with a fresh ID merely to bypass that conflict.

## Implemented Deck application boundary

The backend [Deck application](../../backend/src/decks/application.ts) owns authorization, metadata patches, quantity/role operations, printing replacement, import/export, legality and ownership/availability reads. [Deck contracts](../../contracts/src/decks.ts) explicitly map DTO fields, ISO timestamps and decimal revisions. Web actions and HTTP routes call the same trusted-actor interface. Frontend owns cookies/origins, native form adaptation, errors and drafts. Existing Account Dashboard use cases remain the summary owner.

Library reads return Deck metadata, SQL totals and covers. Only the selected Deck composition is loaded, with Inventory quantities aggregated by its canonical identities. Contextual search and inspector ownership use bounded identities instead of full Inventory or mutation-request history. [Postgres](./postgres.md#deck-persistence-and-reads) owns consistency and supported aggregate ranges; [the HTTP contract](./mobile-and-scan.md#deck-http-contract) records the experimental v1 migration.

Deck metadata patches change supplied fields. Description saves require the original `descriptionRevision`; quantity, role and unrelated metadata changes do not advance it. A stale save returns the latest saved text/revision while the frontend retains the draft for explicit rebase. Native metadata baselines prevent stale unchanged fields from overwriting independent saves.

New Deck entry mutations persist compact original acknowledgements atomically with their fingerprints. Replays return the original result after later edits, entry recreation or Deck deletion. Lookup precedes Catalog resolution, so recorded retries work when Catalog is unavailable. Fresh additions and printing replacements resolve authoritative Catalog identity, name, set and image before the transaction; caller presentation fields do not become stored identity. Legacy null acknowledgements suppress repeated writes without inventing historical results.

Ordinary signed negative quantity deltas stop at one inside the transaction. A floor no-op returns delta zero without advancing `compositionRevision` or rewriting the entry timestamp. Absolute setters, bulk decrement and explicit Remove retain their deletion semantics. Printing replacement requires the same canonical card. An unmerged source keeps its ID and creation time; a merge keeps destination identity/provenance and removes the source. Category-aware merging remains future work. Shared Deck controls/layout remain slice 6, categories slice 15 onward and workspace synchronization slice 9.

## Inventory query contract

Backend accepts normalized filters, the existing composite order, optional group, offset and bounded limit. Start with 50 entries and a maximum of 100 per request. Preserve name/set/newest and variant-order transitions with stable printing/finish/condition/entry-ID ties. PostgreSQL ICU root collation makes name/set ordering canonical; UUID ties are byte-stable. [Migration 0011](../../frontend/drizzle/0011_inventory_windows.sql) creates `inventory_root`, validates the accepted ordering examples and checks the actual ICU version, failing when the required collation is unavailable. It adds the Inventory name/set ordering index and Inventory/Notes revision columns. [Deployment](../operations/deployment.md#inventory-collation-and-recovery) owns version-change recovery.

A read-only local probe matched the current Node en-US comparator for these examples: `10, 100_, 100%, 2, A B, A-B, AB, aether, Aether, Æther, Angel, Ángel, Eclair, éclair, Other, Öther, 卡牌, 土地`. This is limited example evidence. A client locale's former order can differ from the accepted server order. The declared local scale scenarios are verified with [slice 3](https://github.com/KyleDerZweite/spellbook/issues/176); other ordering cases remain unverified.

Search uses literal case-insensitive substrings of name, set code, condition and Notes, escaping percent and underscore. Selected sets combine with OR; text, sets, finish, condition and group combine with AND. Group membership joins cannot duplicate entries. Summary fields distinguish entry count, copy count, distinct canonical-card count and set count. Inventory's foil-entry count remains separate from Dashboard's foil-copy count. Overlapping groups are never summed as global holdings.

One short consistent database read returns query identity, revision, page, matching entry/copy counts, global totals and complete group counts. Loaded entries include their memberships. Owned set options and one-set progress remain complete metadata. One-set progress keeps its current independence from group/text/finish/condition filters. Later pages require the active revision; changed revisions explicitly reset the window instead of mixing versions.

Expose an authorized single-entry read with its text revision/memberships and an entry-location operation. Location accepts normalized query, entry ID and expected revision, returning its matching absolute index, not-in-query or RevisionChanged. It shares page ordering and read consistency. The frontend does not find anchors by loading preceding pages. Removal reanchors to captured surviving neighbor IDs, then the existing Search/empty-state target.

Native GET URLs use `q`, repeated `set`, `finish`, `condition`, `sort`, `dir`, `variant`, `variantDir`, `view`, `group` and one-based `page`. HTTP queries share the normalizer with offset/limit. Links and form return locations preserve the query. Invalid limits, directions, scopes or IDs fail validation.

## Frontend state and shared controls

InventoryWindow owns cancellation, stale-response guards, revision coherence and bounded cache eviction. The [InventoryWindow](../../frontend/src/lib/inventory/window.ts) contract sets four query contexts, twenty cached pages globally, three concurrent requests and a twelve-page planning range. Same-query scroll replanning prunes obsolete queued pages while active reads finish within their existing slots. Replacing a filter cancels old work and waits for transport slots. The declared local browser and scale scenarios are verified with [slice 3](https://github.com/KyleDerZweite/spellbook/issues/176). Entry, row and measurement maps evict with pages, except a small bounded set of focused/dialog/pending snapshots. Logout/account changes clear account caches.

The implemented [VirtualInventoryList](../../frontend/src/lib/components/inventory/VirtualInventoryList.svelte) owns variable row geometry, visible indexes, overscan and stable scroll anchors using the existing ScrollArea viewport. Labels remain readable rather than clipped to enforce fixed row heights. Routes own dirty drafts, stable inspector documents, pending operation IDs and logical focus outside the page cache. Eviction cannot discard this state. Refresh reanchors by entry ID and preserves intra-row position where possible. Window anchor restoration checks account/query generation, revision and cancellation after location, target-page loading and the final render tick. Revision drift permits one coherent reset/retry; cancelled or replaced work cannot move scroll or restore focus. It never loads preceding pages to locate an entry. A changed Remove quantity needs an updated consequence before commit. A remotely deleted target retains its draft and shows the deletion. Native page links and forms provide the bounded no-JavaScript fallback.

Inventory forms derive their action URL from the current Inventory shallow URL, a same-origin Inventory Search background, or the native loaded URL. Successful enhanced Inventory and Group actions refresh the active bounded window through its shared transport gate, preserving the native page offset and logical anchor. They do not reload the older rendered query. A background Search refresh cannot replace the active shallow query with that older result. Save completion clears a draft only if its entry, Notes and quantity still match the submitted values. Newer edits remain dirty. Native forms and genuine redirects retain normal navigation.

Native offset restoration waits for the hydrated list binding and checks account/window identity after each render tick. Target detail reads apply only to the newest refresh in the same account/window and target lifetime, including after body decoding. Closing or switching a target prunes its snapshot when the pending pin is released. These reads cannot overwrite a newer saved inspector state or repopulate a closed target.

Keep CatalogWindow separate because catalog generations and mutable account revisions have different lifecycles. Reuse transport/range helpers only for actual duplication. Inventory now uses shared Button, WorkspaceHeader and QuantityControl components. Shared Button owns Primary, Secondary, Ghost and Destructive purposes, geometry, pending and focus behavior. Text/navigation links retain underline hover; icon Ghost actions retain background hover. Preserve native anchor/submit and Bits trigger semantics. WorkspaceHeader accepts title, metadata and actions. QuantityControl and existing dialog lifecycle provide shared rendering while Inventory and Deck callers retain data/mutation ownership. Deck Library/editor use explicit feature inputs without an Inventory loading superclass. Preserve the accepted Search toolbar, Home, Settings, fonts and brand.

## Saved-state synchronization

SavedState transport and Profile synchronization are implemented. [saved-state.ts](../../contracts/src/saved-state.ts) owns coarse events and subscriptions; the backend [SavedState application](../../backend/src/saved-state/application.ts) owns account-scoped PostgreSQL LISTEN/NOTIFY fanout. Database commit triggers notify account identity and one coarse topic without documents or credentials. Rollbacks produce no notification. Each process lazily opens one dedicated listener on `spellbook_saved_state`, identified by `spellbook_saved_state:<processPID>`.

Subscriptions register before the initial reset. SSE `reset`, `recovering` and `auth-expired` contain empty data; `invalidate` contains only topics. Stream events contain no account ID, document text, credential or event ID. There is no durable replay or outbox. Current-state refetch recovers missed signals without sticky sessions. [Authentication](./auth.md#saved-state-stream) owns cookie/bearer and origin policy.

The backend binds streams to its private trusted actor/session identity and database expiry. It revalidates sessions every ten seconds and starts a fresh session read immediately before framing each protected delivery. Reserved events remain bound to their subscription and listener epoch until backend `deliver(event)` authorizes the write. Auth notifications remain control and expiry is not extended. Listener loss emits `recovering` and suppresses protected fanout. Reconnect retries after 500 milliseconds and revalidates every attached session before reset/fanout resumes. Revocation discards queued and reserved protected events, substitutes `auth-expired` where possible and disposes the subscription. Listener outage replaces stale reservations with current control handling, including events retained across a heartbeat or downstream pause. Bytes already delivered to a socket cannot be withdrawn.

Each subscriber retains coalesced topic invalidation and control events, without saved documents. The server-only [stream adapter](../../frontend/src/lib/server/saved-state/stream.ts) owns framing and calls backend delivery authorization immediately before writing. It uses a zero high-water mark for socket backpressure, comment heartbeats every fifteen seconds and abort cleanup. An undrained queued subscription is disposed after thirty seconds. The transport preserves bounded queues during slow-consumer and listener recovery.

Subscription setup accepts the contract's structural cancellation interface, without framework or platform types. The HTTP adapter maps request cancellation before setup. Aborted setup promptly removes timers and attachment; late completion cannot reattach the subscriber. One subscriber's cancellation does not cancel shared listener setup. PostgreSQL connection/query waits, authority reads and recovery checks have five-second operation deadlines. Coalesced periodic/fanout validation retains one underlying read during a stall; final delivery always starts a fresh read.

The implemented [Profile consumer](../../frontend/src/lib/saved-state/profile.svelte.ts) refetches current Profile state on reset, Profile invalidation, reconnect and visible resume/online. One read runs at a time with a coalesced follow-up; generation/abort checks discard previous-account responses. Clean fields update while dirty drafts retain their saved baselines. Auth expiry closes the stream, aborts reads and clears protected Profile/header state. [Frontend](./frontend.md#profile-saved-state-consumer) owns editor behavior.

Inventory/Deck/Scan cache invalidation and derived workspace summaries remain slice 9. Healthy connected clients retain the accepted approximately two-second visibility target. Standalone Profile browser evidence covers saved updates, dirty-field retention, account isolation, reconnect/read recovery and expiry cleanup. It does not establish workspace slice 9 or deployed proxy behavior. Outages remain visible and recovery refetches current state. Offline writes and closed-app push remain outside this pass.
