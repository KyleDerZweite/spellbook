# UI library evaluation

- Status: Canonical research reference, replacement deferred
- Last Reviewed: 2026-10-03
- Source of Truth: repository code, upstream documentation and component source, npm metadata, GitHub repository metadata
- Update Triggers: UI redesign, library selection or major upgrade, maintenance changes, unresolved interaction defects, new workflow requirements
- Related Docs: [Reference index](./README.md), [Bits UI documentation](./bits-ui.md), [Frontend architecture](../architecture/frontend.md), [UI design direction](../product/ui-design-direction.md), [Product specification](../product/specification.md)

Shortlist shadcn-svelte with Bits UI, Skeleton, and DaisyUI for the deferred redesign in [issue #168](https://github.com/KyleDerZweite/spellbook/issues/168). They offer distinct choices about component ownership and styling. No replacement is selected or installed by this review. The [design direction](../product/ui-design-direction.md) owns future branding and layout requirements; the current palette does not constrain this comparison.

The current application uses Bits UI, Svelte 5, Tailwind 4, SvelteKit 3, and Node 26. Its [manifest](../../frontend/package.json), [lockfile](../../frontend/pnpm-lock.yaml), and [stylesheet](../../frontend/src/app.css) own installed versions and styles. Existing Bits controls passed this modernization's type, build, and representative browser checks. Those checks are not a complete accessibility audit. Every alternative below was reviewed through primary sources, without installation or an integration test in Spellbook.

## Future shortlist

| Candidate                                                 | Reason to evaluate                                                                                                                                                | Selection condition                                                                                                                                                                       |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| shadcn-svelte with Bits UI                                | Styled source components provide a starting point while preserving control over card layouts and brand tokens. Bits supplies complex keyboard and focus behavior. | Prefer when Spellbook needs a distinct identity and accepts ownership of copied component code and upstream fixes. Compare selected components against the existing custom Bits controls. |
| Skeleton 5                                                | A coherent theme system and styled Svelte components reduce the amount of shared control styling Spellbook must maintain. Its current generation uses Zag.js.     | Prefer when its density, theme model, and mobile controls fit the workflows with limited overrides. Accept a full token and component migration only after that fit is demonstrated.      |
| DaisyUI 5 with native HTML and selective Bits UI controls | CSS classes and theme variables keep basic controls independent of a Svelte component runtime. Native elements cover simple forms and tables.                     | Prefer when styling consistency is the main gap and native behavior meets most needs. Complex comboboxes, menus, and overlays still require deliberate interaction ownership.             |

Carbon is the specialist comparison if dense inventory tables become the decisive requirement. It offers mature table, toolbar, and pagination components, but adopting its visual system would be a substantial change. None of these libraries supplies Spellbook's printing selection, deck availability, inventory ledger, or recognition review logic.

A later comparison should implement the same small slice in the shortlisted candidates: an inventory table with quantity editing, a printing selector inside a dialog, and a narrow-screen scan confirmation. Compare keyboard and touch behavior, contrast, source changes, production JavaScript and CSS, and theme overrides. This is a selection criterion for the deferred task, not an implemented prototype or an additional project in this change.

## Workflow fit and migration cost

| Family             | Inventory, deck, and mobile fit                                                                                                                                      | Ownership and migration cost                                                                                                                                                                                                                            |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Flowbite Svelte    | Broad styled tables, forms, and dialogs suit ordinary inventory screens. Card rows and scan review remain custom.                                                    | Replace component APIs and theme conventions. Setup adds the Flowbite plugin and source scanning. Published dependencies include Flowbite, Floating UI, ApexCharts, date-fns, and Tailwind helpers.                                                     |
| Skeleton           | Shared themes, forms, and overlays suit a coherent desktop and mobile redesign. Deck-specific content remains custom.                                                | Replace tokens and controls, import core/Svelte/theme CSS, and configure `data-theme`. Svelte package uses Zag.js components and Skeleton helpers.                                                                                                      |
| Melt UI            | Flexible builders allow custom dense layouts and unusual interactions. Both generations leave markup and styling to the application.                                 | Rewrite Bits composition as builder wiring. Current package adds Floating UI, focus-trap, runed, and other helpers. Legacy API adds migration debt without a demonstrated benefit.                                                                      |
| Bits UI            | Strong fit for printing selectors, menus, and dialogs with custom card content. Provides no inventory table or brand system.                                         | Lowest current migration cost, but custom shared styles remain application work. Dependencies include Floating UI, runed, svelte-toolbelt, and tabbable.                                                                                                |
| shadcn-svelte      | Useful styled forms, command controls, dialogs, and table patterns while allowing product-specific layout.                                                           | Own copied source and future fixes. Selected components determine dependencies. Map tokens and `#lib` aliases; do not run a theme initializer over existing CSS without reviewing the generated changes.                                                |
| DaisyUI            | Compact CSS-styled forms and tables fit inventory; responsive classes help scan confirmation.                                                                        | Add a Tailwind CSS plugin and translate tokens/classes. Package metadata has no runtime dependencies. CSS alone does not implement complex keyboard interaction.                                                                                        |
| SVAR Core          | Conventional forms, calendars, tabs, and popups suit administration. Core does not include SVAR Grid, Menu, Toolbar, or Uploader; those are separate packages.       | Add Willow themes and three SVAR helper dependencies, then rewrite controls. A dense deck or inventory table remains application work unless separately evaluated.                                                                                      |
| Carbon             | DataTable, toolbar, and pagination make it the strongest specialist candidate for dense inventory. Responsive adaptation still needs a mobile review.                | Major visual and CSS migration. Published dependencies include flatpickr and `@ibm/telemetry-js`; this review did not establish application-user telemetry behavior. Optional import/CSS optimization adds build integration that needs its own review. |
| Svelte UX          | Table, QuickSearch, MultiSelect, NumberStepper, and InfiniteScroll fit dense data work. Drawer and responsive menus help mobile layouts.                             | Tailwind 3 plugin/token configuration needs adaptation. Broad dependencies include LayerStack helpers, Floating UI, d3 utilities, date-fns, lodash, and Zod. LayerChart is a separate companion, not a required dependency.                             |
| SMUI               | Material tables and density options fit desktop lists; dialog fullscreen mode and touch controls help scan review.                                                   | Material styling requires substantial restyling. Choose individual packages or the larger umbrella; supply theme CSS or a Sass compilation step.                                                                                                        |
| STDF               | Mobile-first BottomSheet, ActionSheet, Stepper, ImagePreview, PullRefresh, and InfiniteScroll fit scan work. No dense DataTable was found in the reviewed inventory. | New v3 tokens, source CSS, theme plugin, and `@any-tdf/common` helper. Weak fit as the sole desktop library; interaction gaps need work.                                                                                                                |
| AgnosticUI         | Generic custom-element controls provide forms and dialogs. No native-Svelte dense table solution was verified.                                                       | Highest integration uncertainty: copied Lit/TypeScript source, decorators, custom-element events and forms, CSS tokens, and shadow styling. Source copying still has Lit, focus-trap, and Floating UI runtime requirements.                             |
| Kampsy UI          | Geist-inspired controls and a mobile modal presentation offer a compact starting point. Dense inventory behavior remains custom.                                     | Replace theme CSS and component APIs. Published runtime dependency is Lucide. Sparse integration evidence compared with the shortlist.                                                                                                                  |
| Svelte Headless UI | Unstyled controls allow custom layouts, but this unofficial Headless UI port targets Svelte 3.                                                                       | Reject for a new Svelte 5 migration without a maintained compatible successor. Historical accessibility work does not resolve its peer incompatibility and old release track.                                                                           |
| Sveltestrap        | Conventional Bootstrap tables, forms, pagination, and responsive modal/grid layouts cover ordinary inventory screens.                                                | Introduces Bootstrap CSS/reset and tokens alongside or instead of Tailwind. Uses Popper 2, without Bootstrap JavaScript or jQuery. Broad caller and theme rewrite.                                                                                      |

Dependency lists identify maintenance and integration work, not browser bundle measurements. Tree-shaking, import paths, selected components, and CSS output affect production cost. No alternative's size or speed was measured.

SvelteKit 3 integration remains untested for every alternative. shadcn's CLI has a package-import `#lib` fixture, but its installation guide still illustrates `$lib` and older alias configuration. Verify generated import extensions and TypeScript 7 resolution. Skeleton's guide names Kit 2; Kampsy and STDF develop against Kit 2. DaisyUI's framework-independent CSS reduces coupling, but its generated CSS still needs a build check. AgnosticUI additionally needs SSR, hydration, decorators, custom-element forms, and events verified. A permissive peer range does not settle these questions.

## Accessibility evidence

Library claims do not establish application accessibility. The following evidence comes from inspected upstream tests or source, not a full audit. A missing behavior in one inspected component is a specific gap, not a verdict on every component in that library.

| Family                    | Evidence and remaining question                                                                                                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Bits UI and shadcn-svelte | Bits dialog browser tests cover focus trapping/restoration, nested dialogs, and ARIA relationships. Select tests cover keyboard navigation, Escape, and form values. Copied shadcn markup and local changes still need application checks. |
| Skeleton                  | Uses Zag.js behavior. Inspected Svelte dialog tests assert rendered parts; those tests alone do not establish keyboard or focus correctness.                                                                                               |
| Flowbite Svelte           | Dialog source uses native `dialog.showModal()`, cancellation handling, and initial focus selection. Verify accessible naming and composed form behavior.                                                                                   |
| Melt UI                   | Both generations expose headless interaction builders; published dependencies include focus-trap. No comparable comprehensive interaction test suite was verified in this review. Correct builder wiring remains application-owned.        |
| DaisyUI                   | Semantic HTML and native controls can supply behavior. Its inspected button accessibility documentation is explicitly stale and incomplete. Test the chosen dialog/menu pattern, not a general accessibility claim.                        |
| SVAR Core                 | Inspected Modal handles initial focus and Enter/Escape. It does not implement dialog ARIA, focus containment, or restoration in that component.                                                                                            |
| Carbon                    | Modal source contains focus trapping, initial and restored focus, Escape handling, dialog role, `aria-modal`, and label associations. Validate adapted table and modal flows.                                                              |
| Svelte UX                 | Dialog source supplies a dialog role, Escape handling, and focus movement/restoration. Focus containment and complete naming need further proof.                                                                                           |
| SMUI                      | Dialog source contains focus trapping/release, Escape handling, `alertdialog` role, and `aria-modal`. Check that role and focus behavior fit the selected workflow.                                                                        |
| STDF                      | Dialog and Modal delegate to Popup. Inspected Popup lacks keyboard handling, dialog ARIA, and focus management. These need implementation or a different overlay before replacing current dialogs.                                         |
| AgnosticUI                | Dialog source uses focus-trap with restoration, Escape, dialog role, and `aria-modal`. Svelte integration and shadow-DOM composition remain untested.                                                                                      |
| Kampsy UI                 | Playwright modal tests assert accessible title/description, Escape dismissal, and restored trigger focus. They do not establish all keyboard, touch, or contrast behavior.                                                                 |
| Svelte Headless UI        | Historical dialog tests and accessibility assertions exist. The unsupported Svelte peer and old maintenance track still exclude it from the shortlist.                                                                                     |
| Sveltestrap               | Modal source supplies initial/restored focus, Escape, role, and label association. Tab containment was not apparent in the inspected component.                                                                                            |

The [interface acceptance checks](../product/specification.md#interface-acceptance) and [interaction rules](../product/ui-design-direction.md#visual-and-interaction-rules) own Spellbook's requirements. Any later adoption must check keyboard operation, focus, accessible names, touch targets, reduced motion, contrast, and mutation feedback in the composed workflows.
