# Catalog and database assessment

- Status: Canonical research reference
- Last Reviewed: 2026-10-03
- Source of Truth: repository code, functional probes, tagged releases, primary documentation
- Update Triggers: search requirements, measured resource limits, availability targets, database releases and licensing
- Related Docs: [Reference](./README.md), [Catalog](../architecture/catalog.md), [Worker](../architecture/worker.md), [ADR-0010](../decisions/0010-postgres-catalog.md), [Backend language](../architecture/backend-language.md)

Spellbook now uses its existing PostgreSQL service for catalog storage and search. [ADR-0010](../decisions/0010-postgres-catalog.md) records the service-reduction decision. No full-catalog benchmark establishes that PostgreSQL is faster than the alternatives. The [catalog document](../architecture/catalog.md) owns implemented behavior.

## Catalog choices

| Choice          | Evidence and fit                                                                                                                                  | Main tradeoff                                                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| PostgreSQL 18   | Existing database, full-text search, trigram matching, structured filters, exact printing identity, transactional publication                     | Catalog queries and refreshes share resources with account transactions                                                          |
| Embedded SQLite | Functional prototype passed exact, prefix, Japanese-name and CJK substring search, grouping, facets, filtering, import resolution, and pagination | FTS5 does not supply typo matching; publishing files across application processes requires explicit reader-lifetime coordination |
| MeiliSearch     | Maintained dedicated search engine with typo tolerance, facets, and distinct results                                                              | Retains a separate service, credentials, upgrade process, and query adapter                                                      |
| Typesense       | Typo tolerance, facets, exact filters, grouping, and replicated availability                                                                      | Separate service; searchable index resides in memory; grouping and facet equivalence need validation                             |

A small PostgreSQL 18.6 and Node 26.10.0 SQLite prototype used five printings representing four canonical cards. Both passed the functional cases above. PostgreSQL also passed typo matching, concurrent reads during generation publication, and rollback. This demonstrates feasibility, not production capacity or equal multilingual relevance.

PostgreSQL provides [full-text dictionaries and ranking](https://www.postgresql.org/docs/current/textsearch-intro.html), [GIN text indexes](https://www.postgresql.org/docs/current/textsearch-indexes.html), and indexed similarity and substring matching through [`pg_trgm`](https://www.postgresql.org/docs/current/pgtrgm.html). These are building blocks; application SQL still defines grouping, facet counts, and representative-printing selection.

Node 26's [`node:sqlite`](https://nodejs.org/docs/latest-v26.x/api/sqlite.html) is synchronous and has Release Candidate stability. An embedded catalog could use generation-named closed database files and a manifest, with each request retaining its database handle. Renaming or unlinking databases that processes still have open requires care under SQLite's [file-safety rules](https://www.sqlite.org/howtocorrupt.html). Reusing PostgreSQL avoids this additional publication protocol.

MeiliSearch [1.54.3](https://github.com/meilisearch/meilisearch/releases/tag/v1.54.3) was released on 2026-10-01; its [security policy](https://github.com/meilisearch/meilisearch/blob/main/SECURITY.md) supports the latest stable release. [Distinct results](https://www.meilisearch.com/docs/capabilities/full_text_search/how_to/configure_distinct_attribute.md) select the highest-ranked printing, not a guaranteed latest or preferred-language printing. Its [license](https://github.com/meilisearch/meilisearch/blob/v1.54.3/LICENSE) combines an MIT core with BUSL-1.1 enterprise code.

Typesense [30.2](https://github.com/typesense/typesense/releases/tag/v30.2) was released on 2026-04-19. Its [search API](https://typesense.org/docs/30.0/api/search.html) supports grouped results and per-field typo settings. The [sizing guide](https://typesense.org/docs/guide/system-requirements.html) estimates memory at two to three times indexed-field data; that is vendor guidance, not a Spellbook measurement. Its [Raft setup](https://typesense.org/docs/guide/high-availability.html) replicates the full dataset per node, rather than sharding it. Typesense uses [GPLv3](https://github.com/typesense/typesense/blob/v30.2/LICENSE.txt); separate service/API use does not by itself relicense the application.

## Primary database alternatives

Changing the primary database also changes authentication, inventory mutations, ownership checks, migrations, and recovery. None of these alternatives removes that work merely by exposing SQL.

| Choice      | Evidence checked on 2026-10-03                                                                                                             | Decision                                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| Turso       | Embedded engine 0.8.1 is production-ready; the rewritten Cloud offering remains early preview. This differs from established libSQL Cloud. | No demonstrated need to replace PostgreSQL transaction and locking behavior                                                      |
| DuckDB      | 1.5.6 with Node Neo 1.5.6-r.1 supports analytical SQL and transactions                                                                     | Suitable for a future isolated analytical workload; not the current account database                                             |
| CockroachDB | Innovation 26.3.2 and regular 26.2.7 offer distributed SQL, with version-dependent PostgreSQL compatibility                                | Distributed operation adds migration, retry, licensing, and capacity requirements without a current distributed-data requirement |

Turso's [0.8.1 release](https://github.com/tursodatabase/turso/releases/tag/v0.8.1) and [Cloud documentation](https://docs.turso.tech/turso-cloud) distinguish its products. A Node 26 probe confirmed rollback, default second-process locking failure, and missing `FOR UPDATE` and PostgreSQL advisory locks. [Experimental multiprocess access](https://docs.turso.tech/sql-reference/multiprocess-access) permits one writer and does not support MVCC. The rewritten embedded [Drizzle adapter](https://docs.turso.tech/sdk/ts/orm/drizzle) is beta; the existing libSQL adapter is a different integration. [Tantivy full-text search](https://docs.turso.tech/sql-reference/functions/fts) is experimental, and the probe found no FTS5 support. [Last-push-wins synchronization](https://docs.turso.tech/sync/conflict-resolution) does not by itself preserve inventory and authentication invariants.

DuckDB's [concurrency model](https://duckdb.org/docs/current/connect/concurrency.html) supports concurrent writers within a process, with optimistic transaction conflicts. The Node probe confirmed rollback, primary-key and CHECK enforcement, second-writer file-lock failure, and same-row update conflicts. It found no `FOR UPDATE` or PostgreSQL advisory locks; [foreign-key limitations](https://duckdb.org/docs/current/sql/statements/create_table.html#limitations) exclude cascading deletes. A new row remained absent from [full-text search](https://duckdb.org/docs/current/core_extensions/full_text_search) until the index was rebuilt. [Quack remote access](https://duckdb.org/docs/current/quack/overview) is beta, so a blanket claim that all multiprocess access is impossible would be inaccurate. DuckDB [1.5.6](https://github.com/duckdb/duckdb/releases/tag/v1.5.6) uses the MIT license.

CockroachDB [26.3](https://www.cockroachlabs.com/docs/releases/v26.3) supports transaction advisory locks that [26.2](https://www.cockroachlabs.com/docs/releases/v26.2) does not implement equivalently. The repository's exact PostgreSQL expressions still need compatibility verification. Native [full-text search](https://www.cockroachlabs.com/docs/stable/full-text-search) and [trigram indexes](https://www.cockroachlabs.com/docs/stable/trigram-indexes) exist, but its trigram operators do not reproduce PostgreSQL's full word-similarity and distance set. Serializable transactions and `FOR UPDATE` still require [40001 retry handling](https://www.cockroachlabs.com/docs/stable/transaction-retry-error-reference). The dedicated [Drizzle adapter](https://orm.drizzle.team/docs/get-started-cockroach) is in 1.0 release candidates; the installed stable Drizzle version lacks those exports.

CockroachDB uses the [CockroachDB Software License](https://www.cockroachlabs.com/cockroachdb-software-license/), not its former Core open-source model. Its [free-license conditions](https://www.cockroachlabs.com/docs/stable/licensing-faqs) include an aggregate revenue threshold, annual key, and telemetry. A prolonged telemetry outage can throttle transaction concurrency. Three nodes are needed to tolerate one failed node; [production recommendations](https://www.cockroachlabs.com/docs/stable/recommended-production-settings) impose a larger operating footprint than the current single PostgreSQL service.

## Remaining evidence

Use one fixed multilingual Scryfall snapshot and equivalent fields for any production comparison. Include exact printing IDs, import hints, alternate printings, translated face text, accents, non-Latin scripts, and typing mistakes. Compare selected results and facet counts before throughput.

Measure p95 and p99 latency during normal reads and a full refresh, peak memory, disk usage, publication duration, and account-transaction latency. Include failed publication, concurrent readers, recovery, and every replica required by an availability target. A search-engine decision does not require a Go rewrite; the [backend language assessment](../architecture/backend-language.md) addresses that separate question.
